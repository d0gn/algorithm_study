# 문제 설명
경화는 과수원에서 귤을 수확했습니다. 경화는 수확한 귤 중 'k'개를 골라 상자 하나에 담아 판매하려고 합니다. 그런데 수확한 귤의 크기가 일정하지 않아 보기에 좋지 않다고 생각한 경화는 귤을 크기별로 분류했을 때 서로 다른 종류의 수를 최소화하고 싶습니다.

예를 들어, 경화가 수확한 귤 8개의 크기가 [1, 3, 2, 5, 4, 5, 2, 3] 이라고 합시다. 경화가 귤 6개를 판매하고 싶다면, 크기가 1, 4인 귤을 제외한 여섯 개의 귤을 상자에 담으면, 귤의 크기의 종류가 2, 3, 5로 총 3가지가 되며 이때가 서로 다른 종류가 최소일 때입니다.

경화가 한 상자에 담으려는 귤의 개수 k와 귤의 크기를 담은 배열 tangerine이 매개변수로 주어집니다. 경화가 귤 k개를 고를 때 크기가 서로 다른 종류의 수의 최솟값을 return 하도록 solution 함수를 작성해주세요.

제한사항
1 ≤ k ≤ tangerine의 길이 ≤ 100,000
1 ≤ tangerine의 원소 ≤ 10,000,000


# 문제 풀이

제한사항의 귤 크기는 1000만 이하인걸 보고 배열 1000만 짜리를 생성하며 귤 크기만큼 모두 집어 넣 고
역 정렬 시켜서 앞에서부터 원소를 꺼내어가며 그 원소의 크기가 k 값을 넘으면 리턴하도록 구성했다
결과는 통과이나 문제점이 몇몇 있다 메모리 낭비가 심하고, 정렬 과정중에 1000만개의 원소를 정렬해야 함으로 시간낭비가 발생한다.

이를 개선하기 위해서 
from collections import Counter 의 Counter(리스트) 함수를 사용하여 카운팅 한다
해당 함수는 리스트 안의 값이 각각 몇 번씩 나오는지 카운팅 해주는 함수 이다. 반환은 딕셔너리로 한다. 
일반 딕셔너리를 사용하여 반복문으로 해결 할 수 있지만 keyError를 방지해준다. (딕셔너리 반복문 또한 get을 통해 원소를 접근하면 KeyError 방지)
위 방법은 개선책 2
이후 해당 값은 정렬되지 않은 상태임으로 sorted(정렬기준, reverse=T/F)
sorted 함수는 반드시 리스트로 반환하며 정렬하고자 하는 기준을 잘 설정하면 (딕셔너리의 경우 키 기준이 아닌 벨류로 설정) 적절하게 정렬해준다
이후 정렬된 값을 반복문을 통해 꺼내어
total 변수를 설정해서 원소를 더해가며 K를 넘어갈때 브레이크를 통해 빠져나와 결과 값을 리턴한다.
